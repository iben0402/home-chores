# Rooms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The Rooms tab: a grid of rooms; room detail (its empty state for now, since chores don't exist yet); and Manage rooms for admins (add with an icon, rename, reorder, delete with confirmation).

**Spec:**
- [design spec](../specs/2026-11-24-home-chores-design.md): §6 roles, §8.8 rooms.
- Design canvas, page "Rooms": 1a Rooms (admin and member, desktop), 1b Room detail (and empty), 1c Manage rooms (list, reordering, add, rename General, delete). Plus the Copy sheet v1 "Rooms" and "Manage rooms" sections.

**Scope note:** chores arrive in the next plan. Until then, every room shows "All clear". Room detail shows its empty state ("Nothing in {room}", with "Add chore to {room}" linking to `chores/new?room={id}`), and delete has nothing to move. `deleteRoom` gets its "move chores to General" batch in the chores plan, and its tests then.

## Global Constraints
- Copy exactly as in Copy sheet v1. Delete confirmation with no chores: "Delete {room}?" / "It has no chores." (my wording, since the sheet only has the N-chores case).
- Admin-only UI (Manage rooms, rename, delete) is hidden from members. The rules already enforce it.
- General is always first (`order: 0`). It can be renamed but not deleted or moved.
- Room icons: `house`, `cooking-pot`, `bath`, `sofa`, `bed-double`, `shirt`, `trash`, `sprout`.

## Review Focus
1. **Reordering by keyboard and screen reader**, not only drag: the handle takes ArrowUp and ArrowDown, and announces "Bathroom, moved to position 4 of 6."
2. **A drag cancelled or ending outside the list** leaves the order unchanged.
3. **Two admins editing at once:** order values are re-written for all rooms in one batch, so they stay consistent.
4. **A member opening `/h/:hid/rooms/manage` by URL** is sent back to Rooms.
5. **Blank or too-long names** show a field error and never reach Firestore (the rules would reject them anyway).

### Task 1: Data and rules tests
- `src/data/rooms.ts`:
  - `watchRooms(db, hid, cb)` (ordered by `order`);
  - `addRoom(db, hid, { name, icon })` (`order` = max + 1);
  - `updateRoom(db, hid, roomId, { name?, icon? })`;
  - `reorderRooms(db, hid, orderedIds)` (one batch; General stays 0);
  - `deleteRoom(db, hid, roomId)`.
- Emulator tests (`tests/rules/rooms.test.ts`):
  - an admin adds, renames, reorders and deletes;
  - a member is denied each of those;
  - the General room is first, and deleting it is denied.

### Task 2: Components
- `RoomCard`: a button, with `aria-label` "Kitchen, 3 open, 1 overdue"; "All clear" at 0.
- `ConfirmDialog`: `alertdialog`, inert app, Escape cancels, Cancel focused first.
- `IconPicker`: a radiogroup of 8 room icons, with arrow-key navigation.
- `TopBar`: back plus title.
- Tests for each.

### Task 3: Screens
- `/h/:hid/rooms` (RoomsPage): title, hint, 2-column grid, admin "Manage rooms".
- `/h/:hid/rooms/:roomId` (RoomPage): top bar with back, empty state, "Add chore to {room}". An unknown room shows "We couldn’t find that".
- `/h/:hid/rooms/manage` (ManageRoomsPage, admin): the list with drag handle, rename and delete; "Add a room" sheet; rename sheet (General hint); delete ConfirmDialog; pointer drag plus keyboard reorder with a live-region announcement.
- Tests:
  - "member sees no Manage rooms";
  - "admin adds a room";
  - "rename validates the name";
  - "delete asks first";
  - "keyboard reorder announces and saves";
  - "member is sent back from manage".

### Task 4: Verify (`/build-check`, rules suite, browser at phone and desktop, light and dark), then PR.
